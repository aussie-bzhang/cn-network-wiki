# LTE网络架构

LTE（Long-Term Evolution）是4G标准，最重要特点：**全网IP化（取消电路交换）**。

## 网络架构图

```
                       S1-MME接口
UE（手机）             ┌──────────── MME（移动性管理实体）
  │                   │              控制面：鉴权、移动性管理、寻呼
  │ 空口无线链路       │
  ▼                   │
eNB（基站）─X2接口─eNB
  │                   │
  │ S1-U接口          │S11接口
  ▼                   ▼
 S-GW（服务网关）──── S-GW ─── P-GW（PDN网关）──→ 互联网
  （用户面数据转发）          （分配UE IP地址，
                              连接互联网）
```

**三大核心组件**：
- **eNB（演进基站）**：无线接入，eNB间可通过X2接口直接通信（LTE扁平化的关键）
- **MME（移动性管理实体）**：控制面，负责UE鉴权、位置管理、寻呼
- **S-GW/P-GW（网关）**：数据面，负责IP分组转发

## GTP隧道机制

LTE使用**GTP（GPRS隧道协议）**在核心网传输UE的IP分组：

```
UE发送IP分组（目的=百度服务器BD，源=UE的IP）：

  UE → [PDCP封装] → eNB
  eNB → [GTP封装, TEID1, 源=eNB, 目的=S-GW] → S-GW
  S-GW → [GTP封装, TEID2, 源=S-GW, 目的=P-GW] → P-GW
  P-GW → [解封装] → 互联网（目的=BD）
```

**TEID（隧道端点标识符）**：唯一标识每条GTP隧道，用于区分不同UE的流量。

## UE空闲态节能

当UE一段时间无数据业务时：
- **释放**：空口链路（UE-eNB）和 eNB-S-GW 间GTP隧道
- **保持**：S-GW-P-GW 隧道和 UE的IP地址

当有数据到达时（由百度服务器发来）：
1. P-GW缓存分组，通知S-GW
2. S-GW通知MME
3. MME在**跟踪区列表TAL**内寻呼UE
4. UE响应 → 重建空口链路和eNB-S-GW隧道
5. 继续传输

## 跟踪区与TAL

- **TA（跟踪区）**：由若干小区组成，位置管理基本单位
- **TAL（跟踪区列表）**：1-16个TA，UE在TAL内漫游无需向MME报告
- MME寻呼时只在UE所在TAL内广播，减少信令负荷

## 切换过程

1. UE测量并上报邻近小区信号强度
2. eNB决定切换目标小区
3. 新小区建立空口链路，释放旧空口链路
4. eNB-S-GW的GTP隧道从旧eNB切换到新eNB
5. S-GW-P-GW隧道通常**不重建**（覆盖范围大）
6. 切换过程中通信**不中断**

## LTE协议栈（用户面）

```
应用数据
  ↓
PDCP（分组数据汇聚协议）：IP首部压缩
  ↓
RLC（无线链路控制）：ARQ重传，三种可靠性模式
  ↓
MAC（媒体接入控制）：HARQ、调度
  ↓
PHY（物理层）：AMC（自适应调制编码），OFDMA
```
