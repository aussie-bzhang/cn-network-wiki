# OSI七层模型与TCP/IP体系结构

## 背景

1977年ISO成立SC16分委员会，研究网络体系结构和协议，1983年提出**OSI/RM**（开放系统互连参考模型）。

> 但由于TCP/IP已抢先在全球大范围成功运行，OSI最终**只获得了理论研究价值**，互联网实际上采用TCP/IP体系结构。

## 三种体系结构对比

| 层次 | OSI（7层）| TCP/IP（4层）| 本书采用（5层）|
|-----|---------|------------|------------|
| 7 | 应用层 | 应用层 | 应用层 |
| 6 | 表示层 | ↑（合并）| ↑ |
| 5 | 会话层 | ↑（合并）| ↑ |
| 4 | 运输层 | 运输层 | 运输层 |
| 3 | 网络层 | 网际层 | 网络层 |
| 2 | 数据链路层 | 网络接口层 | 数据链路层 |
| 1 | 物理层 | ↑（合并）| 物理层 |

## 分层的意义

各层独立完成各自功能，各层之间通过**服务访问点（SAP）**交互：

- **服务**：下层向上层提供的功能（垂直关系）
- **协议**：同层对等实体间的规则（水平关系）
- **接口**：相邻层间交换信息的方式

## 协议数据单元（PDU）名称

| 层次 | PDU名称 |
|-----|--------|
| 应用层 | 报文（Message）|
| 运输层 | 报文段（Segment，TCP）/ 用户数据报（UDP）|
| 网络层 | IP数据报 / 分组（Packet）|
| 数据链路层 | 帧（Frame）|
| 物理层 | 比特（Bit）|

## 封装与解封装

```
发送端（由上到下封装）：
  应用数据
    → 加运输层首部 → 报文段
      → 加网络层首部 → IP数据报
        → 加链路层首部+尾部 → 帧
          → 转为比特流发送

接收端（由下到上解封装）：逆过程
```

## 为何TCP/IP胜出

- 1993年以前，互联网已全球运行，TCP/IP已是事实标准
- OSI标准过于复杂，实现难度大
- TCP/IP简单实用，"尽最大努力交付"设计哲学更适合互联网规模
